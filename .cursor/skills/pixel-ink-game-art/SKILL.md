# 像素墨色游戏表现

把用户的游戏策划实现为可玩的二维表现。继承的是灰阶、像素材质、稀疏点彩和短促反馈组成的视觉语言；对象、布局、节奏和声音随游戏内容设计。用户已在 The Called 的主菜单、探索地图、构筑和对局中认可这套感觉。

新游戏或整体换表现按下列步骤执行。局部扩展先读取现有的美术方向与主题，只加载对象、反馈或字体音频的相关参考，实施请求的范围，并验证受影响的实际操作路径。

## 先固定什么

- **双层。** 世界、对象和碎屑使用统一逻辑像素栅格，再以最近邻放大。正文、中文、控件和焦点单独清晰渲染。最终绘制坐标落在逻辑像素上，模拟与补间仍可使用连续值。
- **灰阶。** 背景接近黑色，地面和轮廓由有限灰阶分出层次。用像素接缝、裂纹、阴影和 Bayer 抖动建立材质与空间。
- **点彩。** 高饱和色用于当前动作、阵营、资源、危险和反馈。同一个语义保持同一颜色。大部分画面留在灰阶中。
- **轮廓。** 每类对象有能辨认的剪影、稳定的锚点和一处功能性亮点。对象的形状来自策划语义。
- **节拍。** 输入先确认，再表现准备、发生、结果和恢复。小动作反馈短，重大事件才使用更强的闪白、碎屑和震动。

这些是风格不变式。对象是生物、机器、建筑、工具、地形还是抽象标记，采用什么界面布局，都由策划决定。

## 1. 把策划映射成画面

读策划和现有工程，列出玩家的核心循环、主要对象、状态、操作、需要预判的信息与胜负或完成条件。新项目未规定引擎时，采用 Canvas 2D 世界与清晰的 DOM 界面；已有项目沿用其引擎和规则接口。选择具体适配方式时读 [engine-adapters.md](references/engine-adapters.md)。

在项目中保存一份简短的 `art-direction.md`，记录：

- 游戏内名词对应的剪影、材质和状态变化。
- 每个颜色对应的语义，以及当前场景的主次焦点。
- 一次核心操作如何从输入走到结果，在哪些节点触发画面与声音。
- 逻辑分辨率、最小设备、文字体系和音频情绪。
- 哪些参数可以变化，哪些风格不变式需要保持。

用 [visual-language.md](references/visual-language.md) 和 [theme.json](assets/theme.json) 作基线。数值是起点，可按玩法、设备和用户要求调整。卡牌、九宫格、房间地图与水晶菜单是示例；每款游戏重新按策划选择对象、场景和构图。

**完成条件：** 核心循环的每个状态与操作都有画面落点；每种高饱和色都有语义；布局已包含主操作、预判信息和结果阅读位置。

## 2. 先做一条真的操作路径

实现一个实际场景，让玩家可以执行策划中的核心操作并看到正确结果。新项目先接通最小规则循环；改造项目使用现有状态、合法动作与事件。反馈从已接受的操作或实际状态变化产生，视觉层保持展示职责。

按双层建立像素世界与清晰界面。对象绘制前读 [object-grammar.md](references/object-grammar.md)；制作操作反馈时读 [feedback.md](references/feedback.md)。让选中、悬停、禁用、无效输入、成功与失败各有可辨认的表现，输入设备以策划和目标平台为准。

Web 项目可运行 `node scripts/scaffold.mjs <目标目录>`，把绘制、音频、字体和主题资源复制到项目的 `art/`。基础 API 见 [web-kit.md](references/web-kit.md)。这些模块是可改造的绘制工具，不含游戏规则。其他引擎按相同机制实现，不必依赖 JavaScript。

**完成条件：** 通过真实输入完成一次核心循环；操作对象、可操作范围与结果可读；画面来自实际状态；中文和声音在目标运行环境可用。

## 3. 按对象家族扩展

为每个对象家族定义基础轮廓、局部零件、锚点、材质、状态标记和动作参数。先做可区分的家族，再扩展家族内变体。把方向、体型、资源量、损伤、装备或成长作为有意义的变化轴。

在画面不变式内自由设计。动作游戏的弹道和冲击、经营游戏的工作和产出、解谜游戏的机关与连通、探索游戏的移动与发现都可以拥有自己的形状与节奏。改变对象语义时，同时调整剪影、动作重心和声音频谱。

让对象适配空闲、操作中、结果和异常状态。固定内容 ID 决定外观变体，实体 ID 决定动画相位。绘制随机性只影响美术；规则的随机、时序与合法性仍属于游戏本身。

**完成条件：** 每个主要对象家族在灰阶剪影中可区分；重要状态有明确差别；扩展一个变体无需重写整套绘制与反馈代码。

## 4. 把界面、字体和音频做齐

完成主入口、玩法界面、设置、完成或失败界面，以及策划需要的其他页面。页面共用材质、边框、焦点、提示和转场语言，布局按用途调整。小屏的详细信息用展开区、滚动或重排保持可达。

在排版与声音阶段读 [type-and-audio.md](references/type-and-audio.md)。包内包含像素拉丁字体 Silkscreen、中文 Noto Sans SC、各自授权文件，以及可再生成的 WAV 语义音效。正文以可读性优先；标题与数字可以采用像素字体。根据策划的情绪和事件设计声音，使用独立的音乐与音效控制，先处理音频解锁和加载，再触发播放。

使用 [feedback.md](references/feedback.md) 的优先级控制同时发生的反馈。持续工作、移动和战斗分别分配反馈密度；成功音、危险音与重大事件才提升强度。

**完成条件：** 实际字形覆盖游戏文本；音频在真实输入后可听，音量和静音确实生效；首入、返回、暂停或页面隐藏后没有重复播放与残留动画。

## 5. 运行、看、听，再交付

按 [acceptance.md](references/acceptance.md) 验证真实游戏。在目标尺寸操作核心循环，检查截图和连续动画；试听关键音效与背景混音。能力与素材检查可用 `node scripts/validate-bundle.mjs`，它只验证技能包和素材完整性，不能替代游戏验收。

为功能、视觉、音频分别记录已通过的检查、实际证据和仍未验证的范围。发现问题就修复并重跑受影响路径。若某项因环境限制无法验证，明确记录该项，不把它写成通过。

**完成条件：** 核心循环和关键界面已实际运行；无未处理的运行错误、缺字、断链素材或阻塞操作；动画与声音已检查；交付包含启动方法、实际截图或短录屏与验证结果。

## 参考与迁移

美术标尺使用 [视觉语言](references/visual-language.md) 中的已认可截图。只借鉴画面层次、像素颗粒、节拍和点彩密度，具体对象按新策划重新绘制。若只改一类对象或一种反馈，先读该分支的参考，不必重做整款游戏。

交给另一个 AI 时，传入整个技能文件夹或 ZIP，以及完整策划。可复制 [handoff.md](references/handoff.md) 的提示词。文件路径均相对本技能，不依赖 The Called 工程或原参考网站在线。
