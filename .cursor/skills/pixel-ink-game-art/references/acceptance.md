# 实际验收

## 功能路径

从真实入口开始，完成一条完整核心循环，覆盖正常、无效操作、需要选择的中间状态与完成或失败。变更现有游戏时检查规则结果一致性、输入位置、取消和返回。新游戏按策划验证规则，视觉样例不能代替可玩的交付。

测试使用真实操作与真实状态。为截图注入素材可以用于美术预览，但不得作为玩法路径已经通过的证据。原有测试按改动范围运行，另加能发现实际集成错误的检查。

## 画面与输入

- 在最小目标尺寸、主要桌面尺寸与至少一个窄屏尺寸检查；只针对桌面的项目按其实际最低尺寸检查。
- 截图包括静态布局、主要操作、状态结果和信息最多的场面。动画另看连续运行或短录屏。
- 低清世界的像素大小与材质一致，清晰界面的文字可读。相机移动、缩放、触摸和拖动命中正确。
- 窄屏中的规则、资源、关键动作与结果仍可到达。焦点、选中、禁用和原因能辨认。
- 对象剪影有区别，颜色撤掉后保留主要状态。高饱和色的含义稳定。
- 实际运行无未处理错误，列表身份、重复提交、事件消费和场景退出没有冲突。

以灰阶截图、颜色语义检查和真实玩法可读性判断风格。点彩面积、帧率和逻辑分辨率是诊断数据，不是审美合格证。

策划要求单屏时，在初始、最长反馈、完成或失败、设置界面分别记录视口尺寸、页面 `scrollWidth/scrollHeight`，以及关键按钮的 `getBoundingClientRect()`。同时检查矮桌面和窄屏；标题、计数、操作与结果都计入高度预算。策划允许滚动的页面，则通过实际滚动抵达详细信息和下一步操作，检查横向溢出是否符合设计。只测 Canvas 的尺寸不足以判断整页可达。

## 字体与音频

检查真实字形与字体加载，而不是系统回退恰好让空资源看起来成功。覆盖游戏实际文本、动态读数和混排标点。静音、音乐与音效滑块改变真实输出。

第一次真实输入后声音可用；背景与动作声的层次经过试听。密集事件不削波、不把背景叠加多遍。页面隐藏、暂停、返回与重启行为符合策划。

隐藏页检查记录切换前后的 `document.hidden` 和实际事件。自动化环境切换标签仍返回 `false` 时，记录这条路径未到达；合成 `visibilitychange` 只能检查处理函数，不能当作真实隐藏验收。重载、暂停和声音实例数量按各自实际到达的路径记录。

## 性能与交付

在目标设备上记录稳定与繁忙场面的帧耗时。按主题起步设定预算，再按对象数量和设备调整。静态纹理缓存，背景和重复特效有上限，长时间运行后数量不会无限增长。

交付记录分开写：功能检查、画面观察、声音试听、性能数据。附启动方式、实际截图或短录屏、测试结果与未验证范围。技能包的结构验证、合成波形检查、编译成功都不能替代这些实际证据。
