# 引擎适配

先看策划与工程，再选择实现。目标是相同的双层、栅格、材质、点彩和反馈，不要求所有项目使用同一个框架。具体 API 与设置依安装版本的官方文档核实。

| 机制 | Canvas 2D / Web | Unity 2D | Godot 2D |
| --- | --- | --- | --- |
| 低分辨率世界 | 独立低清 Canvas，最近邻显示 | 2D 世界或逻辑 RenderTexture，像素相机与 Point 采样 | Node2D 世界与低清视口，Nearest 纹理过滤 |
| 清晰文字与 UI | DOM 或另一个显示分辨率画布 | 主分辨率 Canvas 或 UI Toolkit，独立字体资源 | 主分辨率 UI 与 CanvasLayer，清晰字体 |
| 稳定像素 | 最终绘制坐标取整，映射 client 坐标 | 统一 PPU、取样与相机运动，规则坐标不依显示像素 | 统一像素尺寸与取样，世界与输入使用相同变换 |
| 组合对象 | 蓝图、几何与零件锚点 | Sprite、层次零件、Prefab 与对象数据 | Sprite2D、子节点锚点与资源数据 |
| 抖动与材质 | 缓存的像素纹理或低清绘制 | 小纹理、材质或适配管线的抖动实现 | 小纹理、CanvasItem 材质或自定义绘制 |
| 反馈 | 事件驱动的 CSS / Canvas / Web Audio | 规则事件驱动动画、粒子、混音组 | 规则信号驱动动画、粒子、音频总线 |

改造现有游戏时，规则模块、存档、碰撞、合法操作和随机保持工程自己的职责。替换绘制与 UI 的同时测试真实输入路径，避免把可见特效当作规则结果。

原生引擎需要实际场景、对象资源、UI 和操作绑定。Web 需要实际页面和可用控件。只提供源文件或只编译通过，都不足以宣称表现完成。

如果目标平台性能不足，先缩减背景更新、缓存材质、限制透明叠加和粒子，再调整逻辑分辨率。保留关键对象、中文与状态反馈的可读性。
