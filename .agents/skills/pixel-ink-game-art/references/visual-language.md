# 视觉语言与构图

本文件定义画面判断依据。默认数值与颜色以 [theme.json](../assets/theme.json) 为准；项目可生成自己的副本并调整参数。

## 灰阶承担空间，颜色承担意义

背景、地面、物体面、边缘、次要文字、主轮廓依次使用主题中的六个灰阶。把背景压暗，让行动对象和重要数字先被看到。通过相邻面的明暗和轮廓开口表达厚度，即使固定俯视也能读出空间。

点彩总面积通常占稳定画面的约 5%–12%，这是观察起点，不是逐帧配额。选中与爆发可短时超出。先给高饱和色分配稳定角色，再画对象。场景同时拥有一至两种主要点彩，其余用于低频状态。选中不等于危险，资源不等于阵营；颜色冲突时用形状、纹理和标签补足区分。

可改变点彩的语义映射，例如青色表示路径、金色表示成熟作物。保持灰阶主导、点彩稀疏，以及同一状态的颜色稳定。

## 逻辑像素与清晰界面

选一个与游戏对象尺度匹配的逻辑分辨率。主题中的基线适合约 16–32 逻辑像素的对象；地图尺寸、拼图规模和多人信息密度可能需要其他分辨率。世界先在逻辑分辨率绘制，关闭线性过滤，按最近邻放大。

统一逻辑像素尺寸，包括线条、粒子、阴影和图标。模拟位置、方向与补间可以连续变化，最终绘制位置量化到逻辑像素。整数缩放优先；空间不足时使用等比例最近邻缩放或重排，检查像素节奏和清晰度。

中文正文、长规则、菜单、设置和焦点保持显示分辨率。正文不和场景一起降采样。世界坐标、画面缩放、UI 命中和拖动坐标使用同一个变换，缩放后操作仍落到正确对象。

## 材质靠结构和颗粒

地面由暗色面、稀疏接缝、缺口、碎石和像素裂纹组成。墙、建筑和大对象以亮上缘、暗下缘或一致方向的阴影分层。颗粒依附材质和形状，主操作附近降低密度。

Bayer 4×4 有序抖动把渐变转为疏密变化，适合雾、光晕、山脊、污染和能量余迹。把静态纹理缓存，状态变化时才重绘。移动摄像机时令抖动依附世界坐标，避免图案随屏幕游动。

发光先画可辨认的亮核心，再画同色稀疏光点和暗色外圈。光的边界仍读得出像素颗粒。浮尘与小型色点数量受主题预算控制，主要动作发生时降低背景竞争。

## 构图随玩法变化

| 玩法需求 | 画面组织 |
| --- | --- |
| 连续移动与反应 | 主对象、可达区域和危险轨迹优先；HUD 留在边缘 |
| 管理与配置 | 主工作区稳定；资源、队列和状态在周边，详细信息按需展开 |
| 棋盘、拼图与机关 | 连接、格位、目标与成功条件清楚；状态变化局部发生 |
| 探索与选择 | 地标、路径、当前位置和将发生的动作形成层级 |
| 阅读与叙事选择 | 清晰文字承担主体，低频像素环境和一个视觉焦点建立气氛 |

这里的构图都可以变化。卡牌、圆形符文和房间地图只是已验证的实例。新的机械、植物、船、人物、运输设施或抽象逻辑节点，应重新设计符合其语义的轮廓。

## 界面与已认可标尺

控件使用方角或少量切角、细边、暗底、局部点彩。悬停用小幅位移、下划线或局部变亮；选中用边角标记和稳定的强调色。主要操作有明确焦点，禁用和等待保留原因或状态提示。界面层按当前任务组织，不自动套用主菜单的左右分栏。
