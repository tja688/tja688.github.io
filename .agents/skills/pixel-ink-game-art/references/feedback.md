# 动画、交互与反馈节拍

## 从输入走到结果

为每个核心操作明确事件和状态：输入确认、可操作范围或准备、提交与执行、结果、恢复。动画反映这些状态，读数来自实际游戏。视觉可以预览目标或轨迹，结果点数、伤害、资源和胜负以规则结果为准。

选择目标与执行动作的先后按策划决定。执行已接受但尚待决策的动作时，保留正确的可见中间状态。输入锁定只覆盖真的不可操作阶段；空闲呼吸和背景粒子不锁输入。

## 一条反馈有一个重心

| 事件 | 重心 | 可组合的表现 |
| --- | --- | --- |
| 悬停与聚焦 | 此处可操作 | 局部变亮、下划线、边角标记、轻音 |
| 选中与准备 | 动作正在指向这里 | 轻位移、路径或范围预览、准备姿态 |
| 无效输入 | 玩家知道原因与下一步 | 局部短晃、原因文本、低音，不改变规则结果 |
| 成功操作与产出 | 结果已发生 | 小型碎屑、局部闪白、实际数值变化、短音 |
| 强冲击或危险 | 玩家需要立刻注意 | 方向性碎屑、短震动、明确状态标记、危险音 |
| 完成或失败 | 结果可以读懂并继续 | 较长停留、清晰结果、有限演出、下一步操作 |

默认时长、振幅和粒子预算见主题的 `motion`。快节奏玩法缩短恢复和 UI 阻塞；回合与配置玩法保留阅读停留，但允许加速。小动作先用一至两种表现，强事件才组合多种。

## 时间与像素

动画使用时间差计算，而非每帧加固定距离。连续曲线负责运动，最终位置落到逻辑像素。像素碎屑与短闪可以采用阶梯时间，角色运动与拖动保持足够连续。准备偏移、入场回弹、衰减震动和浮字有独立参数。

停顿与震动是局部强化。默认只影响视觉时间或镜头；若策划确实需要冻结动作模拟，使用游戏自己的暂停机制，并保留输入与联机时序边界。普通鼠标悬停不触发全屏冲击。

## 空闲与持续动作

低幅空闲通常以秒计，相位错开。持续工作用装置的具体部位运动和状态灯表达，持续移动用方向与步态表达。完成、受伤和收集用一次性事件表达。持续动作不要反复触发一次性奖励音或入场爆发。

背景动效服从操作焦点。主要动作发生时，降低浮尘和非必要发光的竞争。暂停、隐藏页面、销毁对象和切换场景时处理计时器、粒子、监听器和声音生命周期。

## 叠加预算与减少动态

高优先级的危险、玩家关键动作、结果读数优先于一般特效与背景。高频事件合并浮字或聚合碎屑，限制同时爆发和活动声部。相同事件只消费一次；在组件列表中用 `对象类型:实例ID` 与 `效果类型:事件ID` 区分身份。

减少动态时保留颜色、状态文字、方向与结果，压低震动、闪白、位移和背景运动。只关闭动效而丢失状态，不算完成。

## 直接操作

拖动对象时显示与实际命中一致的可用目标。释放时使用当前合法动作或可达规则，取消时清理指针捕获和残留点击。移动端可用点选或拖动，详细说明通过展开或重排保留。键盘、触摸与鼠标均有可辨认的焦点、选中和结果。
